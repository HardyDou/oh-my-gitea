# 产品管理（PM）设计评审纪要

目标：为 Oh My Gitea 的「产品管理」模块做一次敏捷产品管理设计评审，由 10 位产品专家辩论收敛，
产出最终功能清单（分期）与原型交互设计。基准约束：

- Gitea 已是 Issue 原始数据源，已有阶段/子阶段/优先级看板
- 已有：产品档案、产品文档（Markdown）、原型版本构建与托管
- 已有：omg CLI + Agent Skill，Agent 可操作 Issue
- 无权限体系（内网全员可见）；小团队为主，避免重型工具

---

## 二、辩论纪要

### 第 1 轮：产品层的定位

- 林教练：过程管理已零成本获得（看板）。产品层再放"泳道"就是重复建设。
- 顾总监：但需求池不在产品层，Issue 列表就是需求池的幻觉——Issue 良莠不分，没有"这个产品要做哪几件事"的骨架。
- 老铁：同意骨架说。骨架条目≠任务。任务回到 Issue。
- 陈总：总结——**产品层管脉络，Issue 层管执行**。脉络=产品→功能项→版本。
- 秦总监：预留：未来"项目组合"在产品之上再包一层（现在不做）。

**结论 D1**：产品层 = 产品档案 + 功能项（Feature）+ 版本（Release）。执行继续留在 Gitea Issue + 现有阶段看板。

### 第 2 轮：功能项（Feature）的定义与存放

- 老铁：功能项存 PostgreSQL，字段轻：标题、描述(MD)、状态、优先级(P0-P3 复用)、负责人（Gitea 用户）、所属产品、所属版本。
- 阿独立：状态给 5 个就够：`规划中 / 设计中 / 研发中 / 已发布 / 暂缓`。别做成每产品可配置15阶段。
- 顾总监：必须可**关联 Gitea Issue（0..n）**，跨仓库可选；关联后 Issue 的阶段流转即功能项进展的真实来源。
- Kim：Agent 视角——功能项是给 Agent 的"需求卡"：omg 应支持 `omg feature list/add/update/move`。
- 何总监：优先级复用 P0-P3，团队零学习成本。
- 苏博士：增加"来源"字段？先不做，M2 再说。

**结论 D2**：功能项存库；状态固定 5 个；优先级 P0-P3；0..n 关联 Issue（跨仓库）；关联 Issue 的阶段变化即进展。

### 第 3 轮：版本（Release）

- 何总监：Release 是承诺。字段：名称、目标日期、状态、说明、功能项集合。
- 邱经理：功能项放进版本时校验冲突（一个功能项只属一个版本）。
- 旨教练：看板已有阶段；Release 的"完成"以其中功能项全部进入 `已发布` 为准，不自动强约束但给出进度百分比。
- 陈总：M1 做版本卡片列表 + 进度；不做甘特。

**结论 D3**：Release 状态固定 4 个（未开始/进行中/已发布/归档）；进度 = 已发布功能项/总数；不强制排他校验之外的复杂规则。

### 第 4 轮：文档与原型

- 邱经理：文档天然是"需求说明书"，Agent 读产品简介+文档即可写功能项草稿。
- Kim：M1 至少提供 omg 查询命令（产品列表/功能项列表），Skill 文档同步更新。
- UX（会后补充）：文档与原型保持现有页面，挂进产品详情 Tab 即可，不重做。

**结论 D4**：文档、原型沿用现状，纳入产品详情 Tab 迷你统计；Agent 侧 M1 只加查询命令。

### 第 5 轮：度量与概览页

- 苏博士：概览页四件套——功能项状态分布（彩色分段条）、下一版本倒计时、关联 Issue 阶段分布（复用看板配色）、最近动态。
- 阿独立：一个页面 30 秒看完，超过就砍。
- 陈总：同意。趋势图、燃尽放 M2。

**结论 D5**：概览=四件套，一屏。

### 第 6 轮：交互范式（UX 决策）

- UX 参照 Multica 风格：面包屑 + 详情分栏（主区 Tab + 右侧属性栏）
- 新建/编辑：**右侧抽屉**（不跳页、不丢上下文）
- 功能项表格支持**行内快捷改**状态/优先级（点开小 popover 而非整行编辑）
- 关联 Issue 用**多选搜索下拉**：搜索当前可见仓库 Issue，选中即关联

**结论 D6**：抽屉式编辑、行内唤醒、多选搜索关联。

## 三、最终功能清单

### M1（本次原型范围）

1. **产品档案**：列表（卡片+关键计数）、新建/编辑/删除（右侧抽屉）
2. **产品详情信息栏**：面包屑、右侧属性栏（信息/概览统计）
3. **概览 Tab**：功能项状态分布条、下一版本倒计时、关联 Issue 阶段分布、最近动态 4 项
4. **功能项 Tab**：
   - 列表：筛选（状态/优先级/版本）、行内状态/优先级快速修改、点击开抽屉
   - 新建/编辑抽屉：标题、描述(MD+预览切换)、优先级、状态、负责人、所属版本、关联 Issue（多选搜索、可跨仓库、可移除）
   - 删除（确认）
5. **版本 Tab**：
   - 版本卡片：名称、状态徽标、目标日期、进度条、功能项计数
   - 新建/编辑/发布/归档；功能项跨卡片移动（编辑功能项时改"所属版本"）
6. **文档 Tab / 原型 Tab**：沿用现有（文档列表+Gitea 样式 MD 编辑预览；原型 Tag 构建+版本芯片），头部分别挂"文档 N / 原型 N"
7. **Agent/CLI**：`omg products`、`omg product OWNER? ID`、`omg feature list/add/update/move`、`omg release list`；Skill 文档同步
8. **审计**：产品/功能项/版本变更全量写 `audit_log`

### M2（下一期）

- 路线图时间线（横轴月份、按 Release 泳道）
- 趋势/燃尽图（按周快照）
- 从 Issue 反向一键生成功能项
- 文档全文搜索；文档版本快照
- 产品组合层（多产品汇总视图）

### 明确不做

- 权限体系、多级 Epic、工时/甘特、企业报表、需求评审流、客户访问门户

## 四、原型交互设计

### 页面结构

```
产品（列表页）
└─ 产品详情（面包屑：产品 / {产品名}）
   ├─ Tab：概览
   ├─ Tab：功能（N）
   ├─ Tab：版本（N）
   ├─ Tab：文档（N）   ← 沿用现有
   └─ Tab：原型（N）   ← 沿用现有
   右侧栏（详情页常驻）：产品信息 + 概览统计 + 操作（编辑/删除）
```

### 关键交互流

1. **建产品**：列表页「新建产品」→ 右侧抽屉（名称/描述）→ 保存 → 卡片出现；空态卡片引导
2. **进详情**：点卡片 → 面包屑 + 分栏详情；记住上次所在 Tab
3. **建功能项**：功能 Tab「新建功能」→ 抽屉表单：标题必填；描述可用 编辑/预览 Tab；关联 Issue 区支持 `仓库/编号/关键词` 搜索多选；保存后列表插入顶部
4. **推进功能项**：列表行点状态/优先级徽标 → 小 popover 改值，即时保存（失败回滚+提示）；行点开抽屉看完整详情
5. **排版本**：版本 Tab「新建版本」（名称/目标日期/说明）→ 卡片显示进度条；编辑功能项时改"所属版本"即可把进度挂上去；卡片操作：编辑、发布（标注发布日期）、归档
6. **看进展**：概览 Tab 一屏看：状态分布条（五段彩色）+ 下一版本倒计时 + Issue 阶段分布（复用看板列颜色）+ 最近 5 条动态（谁在何时建/改了什么）
7. **切换产品**：面包屑「产品」返回；详情内操作不丢当前筛选
8. **Agent 旁路**：PM 在 Gitea PM 网页操作的同时，Agent 可用 omg 完成同样的 4 类动作，全部进审计

### 组件与状态

- 抽屉：460px 右滑出；Esc 关闭+脏确认；错误回显在字段下
- 徽标：状态（5 色）、优先级（P0 红/P1 橙/P2 蓝/P3 灰，沿用看板）
- 进度条：六段彩色分布条（复用看板列色）；版本进度绿条
- 空态：每 Tab 有引导文案 + 主操作按钮；加载骨架屏；删除需二次确认
- 交互一致性：行内快捷改用 popover；跨 Tab 计数实时刷新；面包屑可点击
